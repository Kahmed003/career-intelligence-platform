## Architecture

Career OS uses Next.js App Router, TypeScript, Supabase Auth/PostgreSQL, and generated database types.

The database remains authoritative for ownership, RLS, constraints, and cross-domain integrity. Repositories are application-side query/write adapters; they do not duplicate database invariants.

### Boundaries

- `src/lib/supabase/browser.ts` — browser client.
- `src/lib/supabase/server.ts` — request-scoped Server Component / Server Action client.
- `src/lib/supabase/database.types.ts` — generated by Supabase CLI; never hand-maintained.
- `src/lib/data/repositories/*` — typed domain persistence.
- UI components do not call `.from(...)` directly.
- Service/workflow code may compose multiple repositories.

## Generated Types

Run:

```bash
npm run db:types
```

The repository expects `database.types.ts` to be generated from the fully migrated database.

## Repository Contract

Repositories:
- accept a typed `SupabaseClient<Database>`;
- rely on RLS for user ownership;
- filter soft-deleted canonical Objects on reads;
- create first-class domains in two phases: canonical Object, then specialized row;
- compensate by deleting the just-created canonical Object if the domain insert fails;
- expose domain-oriented list/get/create/update methods;
- throw `RepositoryError` rather than leaking raw PostgREST errors.

## Transaction Note

Supabase/PostgREST does not provide a general client-side multi-statement transaction. The create helpers use compensating cleanup. For workflows that must be strictly atomic under concurrent production writes, promote them later to controlled PostgreSQL RPC functions.
